# 代理定时任务提示词

将下面流程用于你自己的调度任务，先填好本机工作目录、状态目录和私有配置；不要把值提交到本仓库。调度时间自行设置。

建议主代理：GLM-5.3。核对子代理：DeepSeek-V4.1-Flash 和 Kimi-K3。
若运行平台使用 AliBailian 路由，对应模型名为：
- 主代理：AliBailian/glm-5.3
- 子代理一：AliBailian/deepseek-v4.1-flash
- 子代理二：AliBailian/kimi-k3

模型名称及委派权限取决于部署环境；配置可用的对应模型后运行。子代理不可用时报告，不能谎称核对成功。此文档不会安装模型服务或自动授予委派权限。

## 每日执行指令

1. 在部署目录读取 README 和本机配置。使用同一 RECALL_HOME；密钥由环境提供，不读取或输出密钥文本。
2. 运行 recall status。若 pending，只继续该批 NEW 的核对；若 reviewed，先 recall sync 恢复上传。旧批完成后仍要获取今天的列表。
3. 只读取官网召回列表元数据；翻页覆盖至上次成功检查范围并保留历史重叠。不要按“已入表召回最大日期”截断，也不要重新打开历史正文。
4. 使用 recall fetch 或在官方浏览器中提取完整列表后调用 recall snapshot。空页面、403、日期覆盖不足、标题截断或无法确认完整页序列时报告失败，不写“无新增”。
5. 调用 recall prepare。NEW=0 时不启动子代理，不分析正文，直接 recall sync 写简短当日日志。
6. NEW>0 时只把本批 NEW 链接交给两个子代理。两个子代理独立阅读官方全文并返回日期、公司、车型、数量、缺陷本体和判定。禁止子代理回溯整站历史；只读，不修改文件、不上传。
7. 默认口径：仅缺陷本体为螺栓、螺母、螺钉、螺丝、螺纹等紧固件，且存在松动、断裂、脱落、扭矩不足、漏装、错装等缺陷的机动车召回。仅维修使用紧固件的不算。
8. 主代理逐条以官方正文裁决。双路一致且与原文相符的条目才可 in_table=true、crosscheck_agreed=true，并附 rows。存疑不入表、保留分歧，不自行虚构数量或结论。
9. 按 docs/data-format.md 保存完整 reviews 数组，运行 recall review。不要手工提前向 ledger 写入 NEW。
10. recall sync --dry-run 校验后，运行 recall sync。不得绕过批次上传全量数据。所有日志用纯文本，不使用 Markdown 表格，且不得含本地路径、目录、文件或账户配置。
11. 失败保留批次、快照、判定和日志，下次从未完成步骤恢复。不得删除台账、重新初始化或重新分析已保存的判定来“解决”上传失败。
12. 简短汇报：NEW 数、符合条件的召回行数、本次成功创建/已存在跳过数、日志是否成功。不要在公开对话输出账户或应用标识。
13. 若 run 返回 4，说明只恢复了旧批；继续获取今日列表再运行。返回 3 则进入核对流程。

建议创建本地定时任务并保持状态目录持久化；不要将带真实配置的任务提示词放入公开仓库。
