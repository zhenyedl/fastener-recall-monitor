# 输入与判定格式

所有下列记录都是虚构示例，URL 仅演示结构，不是待处理的真实公告。

## 列表数组

```json
[
  {
    "date": "2020-01-01",
    "title": "虚构测试企业召回部分测试汽车",
    "url": "https://www.samr.gov.cn/zw/zh/art/2020/art_fixture.html"
  }
]
```

可选字段 `company`、`no`、`memo`。正式输入必须来自官方列表的完整标题、日期和链接。不要只选“看起来与螺栓有关”的标题；NEW 的缺陷是否符合条件应在读正文后判断。

`snapshot` 命令将数组包装为带 `checked_at`、`source_urls`、`coverage_since`、`coverage_complete` 的日常快照。当天首次处理必须用新快照，旧批次重试使用其保存的快照。

## 判定数组

每条 NEW 恰好对应一份判定；一份判定的 `rows` 可以有多行。

```json
[
  {
    "date": "2020-01-01",
    "title": "虚构测试企业召回部分测试汽车",
    "url": "https://www.samr.gov.cn/zw/zh/art/2020/art_fixture.html",
    "company": "虚构测试企业",
    "memo": "演示：两个核对方都确认缺陷本体为螺栓",
    "verdict": "螺栓断裂，符合条件",
    "in_table": true,
    "crosscheck_agreed": true,
    "crosscheck": "演示：核对方一与核对方二的日期、数量和缺陷判定一致，主代理已核实",
    "rows": [
      {
        "日期str": "2020-01-01",
        "公司": "虚构测试企业",
        "车型": "测试车型",
        "数量": 2,
        "分类": "螺栓",
        "原因": "测试螺栓断裂",
        "来源URL": "https://www.samr.gov.cn/zw/zh/art/2020/art_fixture.html",
        "备注": ""
      }
    ]
  }
]
```

- 对应关系由 NEW 公告身份强制校验，禁止混入历史或其它公告。
- `in_table` 必须为 JSON 布尔；`数量` 必须为非负整数。
- 只有真实交叉核对一致才设置 `crosscheck_agreed: true`；该字段不是可以跳过核对的开关。
- 首次核对日期默认由保存判定的日期生成。跨日核对可填 `first_checked`，须处于发现日至今天之间。
- 排除或存疑：`in_table: false`、`rows: []`，在 verdict/crosscheck 中解释；存疑需后续人工处理。
- 一旦整个批次保存为 reviewed，重试复用其结果，不要求重新生成判定。
- 批次完整提交台账后不自动重开。需要更正历史判定时先备份并制定明确迁移，不删除台账或重新初始化。

## 纯文本明细

```text
第 1 条
首次核对：2020-01-02
公告日期：2020-01-01
公告：虚构测试企业召回部分测试汽车
公司：虚构测试企业
召回范围：虚构测试企业，测试车型，数量 2
判定：螺栓断裂，符合条件
```

无新增时仅写“当日新增公告 0 条，无逐条判定”。旧批重试保留原首次核对日期；日志运行时间反映实际写入时间。
